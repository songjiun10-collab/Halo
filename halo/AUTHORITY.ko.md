# HALO 실행 권한 경계

`authority.py`는 신뢰된 호스트가 발급한 권한을 실제 메모리 객체 쓰기까지
연결하는 참조 구현이다. 모델이 실패한다는 전제에서 동작한다.

## 연결 계약

1. 호스트가 인증한 사용자 의도만 `Authority.approve`로 전달한다.
   `intent_id`는 추적용 식별자이며 인증 수단이 아니다.
2. 웹·이메일·문서·도구·다른 에이전트의 본문은 DATA다. 본문의 `trusted`,
   `approved` 등 문자열을 승인 입력으로 변환하면 안 된다. 승인 API,
   정책 콜백, 감사 저장소 및 Authority 객체 자체를 모델 도구에 노출하지 않는다.
3. 모델에는 실행 제안을 제출할 `execute` 어댑터만 제공한다. 임의 Python을
   같은 프로세스에서 실행하게 허용하면 이 모듈은 보안 경계가 되지 않는다.
4. 권한은 정확한 action/target/payload, 객체 버전, 만료 시간에 묶인다.
   호스트가 보유한 레지스트리에 없는 토큰, 다른 인스턴스의 토큰,
   취소·만료·재사용된 토큰은 실행을 허용하지 않는다.
5. 실행 시 정책과 만료를 다시 검사한다. 객체 버전 확인과 쓰기는 같은
   잠금 안에서 진행한다. 쓰기 전에 토큰을 소모한다.
6. 승인·실행 의도·실행 결과를 감사 콜백에 전달한다. payload와 capability
   토큰은 기록에 넣지 않는다. 사전 감사 장애는 실행을 거부한다.
   사후 감사 장애는 `AuditAfterCommitError`다. 효과가 이미 발생했으므로
   자동 재시도하지 않는다.

## 현재 검증 범위와 미완료 통합

MemorySandbox는 초기 등록된 객체에 대한 크기 제한 쓰기만 제공한다.
파일·네트워크·프로세스 실행 기능은 없다. 이는 OS sandbox 대체물이 아니다.
인증된 사용자 채널 어댑터, 모델 planner, 실제 도구 실행기, 영속 capability
저장소, 변조 방지 감사 저장소는 아직 연결되지 않았다. 감사 콜백의 성공은
신뢰된 저장소의 기록 보장을 전제로 한다. 분산 트랜잭션을 제공하지 않는다.
기존 safety_cases/ policy는 탐지 평가기이며 그 ALLOW를 capability로 사용하지 않는다.
기존 Seatbelt의 Mach/마운트 메타데이터 노출도 이 변경으로 해결되지 않는다.

검증: `.venv/bin/python -m pytest tests/test_authority.py -q`
