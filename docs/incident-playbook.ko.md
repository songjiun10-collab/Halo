# 사고 대응 매뉴얼 (베타)

대상: 개발자, 그리고 개발자와 연락이 안 될 때 사용자 응대를 맡는 사람.
원칙 세 가지: **먼저 막고, 바로 알리고, 증거를 남긴다.** 원인을 다 알기 전에 "괜찮다"고 말하지 않는다.

## 0. 지금 코드에서 가능한 것과 불가능한 것 (사실 확인 2026-10-13)
- 결제는 사용자가 채팅으로 명확하게 시킨 요청에서만 위임장(mandate)이 생기고, 한 목표(goal)당 한 번만 결제된다. 루틴과 트리거는 위임장을 받지 못한다. (`main/harness/payment-mandate.js`, `task-controller.js`의 `_ensureMandate`)
- **결제 킬 스위치가 있다.** 호스트 설정 `paymentsEnabled`가 `true`가 아니면 위임장을 만들지 않고, 이미 받은 위임장도 취소하며, 결제 클릭은 기존 사람 승인 게이트로 돌아간다(`host-settings.js`, `task-controller.js`). 설정을 끄면 실행 중인 작업에도 바로 적용된다. **값이 없으면 꺼짐이다(결제 기본 거부, 사용자가 명시적으로 켜야 결제된다).** 설정 화면의 **Allow payments** 스위치로 켜고 끈다(켤 때만 확인 창). 코드에서는 `updateHostSettings({ paymentsEnabled: true|false })`.
- 킬 스위치로 막지 못하는 경우(규칙 자체의 버그)는 문제 커밋을 `git revert`해서 새 빌드를 내보낸다.
- 결제 직전까지만 하라는 요청("사지 마")과 송금/이체는 위임장이 생기지 않는다(항상 질문).

## 1. 사고 등급
| 등급 | 예 | 첫 행동 시한 |
|------|----|-------------|
| 심각 | 시키지 않은 결제, 상한 초과 결제, 계정/개인정보 노출 | 15분 안에 사용자 공지 |
| 높음 | 승인 없이 되돌릴 수 없는 클릭, 결제 규칙 우회 가능성 발견(아직 피해 없음) | 1시간 안에 공지 |
| 보통 | 작업이 계속 실패, 잘못된 답, CAPTCHA 반복 | 당일 안에 답장 |

## 2. 심각/높음 사고의 순서
1. **기록부터 3분 안에.** 사용자 메시지 원문, 스크린샷, 시각, 빌드/커밋(`git rev-parse --short HEAD`)을 `docs/incidents/날짜-제목.md`에 붙여 둔다. 나중에 원인을 찾으려면 필요하다.
2. **사용자에게 즉시 경고.** 아래 문구를 베타 공지 채널(레딧/DM)에 올린다. 원인은 몰라도 된다.
3. **막는다.** 결제 관련이면: 먼저 킬 스위치(`paymentsEnabled`를 `false`로)를 내린다. 규칙 버그가 원인이면 문제 커밋을 `git revert`하고 새 빌드를 배포한다.
4. **피해를 확인한다.** 실제 결제 기록(작업 저널, 영수증)에서 해당 빌드로 실행된 결제가 0건인지 본다. "돈은 안 나갔다"는 **확인한 뒤에만** 말한다.
5. **고친다 + 재발 방지.** 원인을 고치고, 그 사고를 잡는 테스트를 추가한다(예: 상한 초과는 질문으로 가야 한다 → `test/task-controller-payment.test.js`). 결제 규칙을 바꾸는 커밋은 다른 사람이 리뷰하거나 최소한 하루 뒤 재검토한다.
6. **결과를 알린다.** 무슨 일이 있었고, 영향이 몇 명이었고, 무엇을 고쳤는지 쓴다.

## 3. 사용자에게 보낼 문구
**경고(즉시):**
> 베타 사용자분들께: 방금 Halo의 결제 처리에서 문제 가능성을 확인했습니다. 원인을 확인하는 동안 **결제가 필요한 작업은 하지 말아 주세요.** 이미 결제가 이뤄졌다면 내용을 알려 주세요. 오늘 안에 결과를 안내드리겠습니다.

**개별 문의 응답(피해 주장):**
> 불편을 드려 죄송합니다. 결제 화면 캡처와 시각을 보내 주시면 확인해서 오늘 안에 결과를 알려드리겠습니다. 환불 여부는 확인 뒤에 안내드리겠습니다.

**하지 않는 말:** "그럴 리 없다", "동의하신 겁니다", 확인 전의 "환불해 드립니다".

## 4. 개발자와 연락이 안 될 때 (합류자/대리인이 할 일)
- 할 수 있는 것: 기록 남기기(2-1), 경고 문구 올리기(2-2), 개별 응답(3).
- 할 수 없는 것: 코드/빌드 변경, 환불 약속, 원인 단정.
- 개발자가 연락되면 `docs/incidents/` 파일 하나만 보여 주면 되게 해 둔다.

## 5. 사고 후 점검 (24시간 안에)
- 무엇이 사고를 만들었나(코드/규칙/설정)? 비슷한 곳이 더 있나?
- 같은 일을 막는 테스트가 있나?
- 사용자에게 알린 시점이 충분히 빨랐나?
- 이 매뉴얼에서 고칠 곳이 있나?
