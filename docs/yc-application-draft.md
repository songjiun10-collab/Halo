# YC 지원서 초안 (2026-10-11)

규칙: 저장소와 측정으로 확인된 내용만 적었습니다. `[입력 필요]`는 저장소에 근거가 없어 사용자가 직접 채워야 합니다. 마감일과 질문 목록은 ycombinator.com/apply에서 직접 확인하세요(이 초안은 일반적으로 알려진 질문 구성을 따랐습니다).

## 한 줄 설명 (50자 내외 영문 권장)

Halo is a desktop browser built for working with AI agents: real Chromium, one isolated browser per agent, and a host-controlled permission layer.

## 무엇을 만드나

- 데스크톱 브라우저. 실제 Chromium 페이지 위에 에이전트, 장기 작업, 팀 룸이 한 작업공간으로 묶여 있습니다 (README 기준).
- 에이전트는 사용자 창과 분리된 숨은 브라우저 뷰에서 일하고, 사용자 창은 그대로 둡니다.
- 권한은 호스트가 통제합니다. 실행 전 lease와 effect 분류를 거칩니다.
- CAPTCHA는 풀거나 우회하지 않습니다. 해당 사이트를 막힌 것으로 표시하고 다른 출처로 우회하거나 사용자에게 넘깁니다 (README 데모, 로컬 목업 페이지 기준).

## 왜 다른가 (설계 사실이며 성능 우위 주장이 아님)

- 에이전트별 렌더러 분리와 사용자 창 비침범.
- Chromium을 소스 수준에서 패치한 포크(`halo` 브랜치, 패치 3개).
- Halowright: 모델이 locator(role/label/text)로 단계를 제안하고, 호스트가 자동 대기와 효과 확인을 하며, 불확실한 부작용은 재시도하지 않습니다.

## 지금까지의 진척 (측정값, 한계 포함)

- 개발 기간: 첫 커밋 2026-09-10, 커밋 292개.
- Online-Mind2Web 과제 20개 ×1회, Haiku 5.5, 수동 비맹검 판정, 최종 화면만 근거: done 6, not_done 3, unclear 6, 한도 초과·정지 4, 미판정 1. 공식 채점이 아닙니다.
- 같은 20개에서 소요 중앙값 39초, 비용 총 약 13.22달러.
- 경쟁 제품(Aside 등)과 같은 과제로 비교한 데이터는 없습니다. 지원서에 "더 빠르다/정확하다"를 쓰지 마세요.

## 사용자·견인력

- `[입력 필요]` 실사용자 수, 사용 빈도, 대기 명단, 인터뷰한 사람 수. 저장소에서는 확인되지 않았습니다.

## 시장과 경쟁

- `[입력 필요]` 목표 사용자와 시장 크기 근거.
- 경쟁: 브라우저에 AI를 덧붙인 제품들(Aside 포함). 차별점은 위 "왜 다른가"의 설계 사실로 쓰되, 성능 비교는 Aside 측정 결과가 생긴 뒤에만 쓰세요.

## 팀과 시간 투입

- `[입력 필요]` 공동창업자 유무와 역할, 각자의 풀타임 여부.
- 주의: 엔트로픽 합류 후 경영권을 넘기고 지분을 파는 계획이 있다면, YC가 기대하는 풀타임 창업자 조건과 충돌합니다. 지원서의 시간 투입 질문에 어떻게 답할지 먼저 정해야 합니다.

## 지원서 전에 정리할 것

1. 데모 영상(1분 안팎): README의 CAPTCHA 우회 데모나 에이전트 홈 화면을 실제 사이트 시나리오로 확장.
2. 사용자 근거 확보: 소수라도 실제 사용 기록.
3. 지분 구조 정리(공동창업자와의 합의서).
4. 메모리 목표(유휴 300 MB 미만)는 TrialLean 기준으로 아직 측정 전이라 수치를 쓰지 마세요.
