# 장기 작업: 복구 예산 보존과 플래너 피드백

## 승인된 범위

원래 목표를 유지하면서 중단·재시작·모델 변경에도 제한된 복구만 수행한다. 모델 가중치를 변경하는 작업이 아니다. 플래너에 호스트가 만든 짧은 실패 대응 힌트를 전달하되, 실행 권한이나 사용자 목표를 수정하지 않는다.

## 구현

- `runtime-src/main/harness/recovery-policy.ts`: 버전 1의 `snapshot()`과 상태 복원. 누적 `spent`와 최대 30개의 최근 시도만 저장한다. 손상된 상태는 기본값으로 초기화하지 않고 거부한다.
- 체크포인트 `recoveryBudget`: `{ version: 1, spent, recent: [{ reason, at }] }`.
- 복구 `note`에도 같은 상태를 기록한다. 기록이 내구화된 이후에만 재시도한다. 마지막 체크포인트 뒤의 기록을 복원할 때 누적 횟수는 정확히 하나씩 증가해야 한다.
- 기록 실패 시 추가 재시도를 하지 않고 기존 중단 경로로 이동한다.
- 체크포인트 `plannerEscalations`와 tail의 `planner_escalation`으로 작업당 모델 상향 횟수를 보존한다. 모델 변경은 최근 복구 창만 초기화하며 전체 누적 한도는 유지한다.
- `progress.recoveryFeedback`: 고정된 호스트 진단만 전달한다. 원본 provider 오류, 웹 텍스트, 사용자 비밀은 복사하지 않는다. `authority`는 `host_diagnostic_not_permission`. 네 가지 고정 원인만 허용하며 각 결과는 512바이트 이하다.
- 새로운 실제 진행은 최근 실패 창을 초기화한다. 누적 한도는 초기화하지 않는다. 재시작 후 새로운 관측은 기존 동작대로 진행으로 간주될 수 있지만 누적 한도를 우회할 수 없다.

기존 목표·승인·epoch·execution_uncertain 검사는 변경하지 않는다. 불확실한 실행은 자동 재시도하지 않는다. 신규 상태가 없는 구버전 체크포인트는 호환을 위해 0부터 시작한다. 구버전에서 기록하지 않았던 과거 시도 수를 소급해서 복원한다고 주장하지 않는다.

## 진단 질문과 신호

1. 재시작 후 복구 횟수가 초기화됐는가? 체크포인트와 tail의 `recoveryBudget.spent`로 확인한다.
2. 같은 작업이 모델 변경을 반복하는가? `plannerEscalations`와 기존 `planner_escalation` 기록으로 확인한다.
3. 다음 플래너 턴이 실패 원인을 받았는가? `progress.recoveryFeedback`의 고정 원인과 횟수로 확인한다.

새 외부 telemetry 서비스나 개인정보 수집은 추가하지 않는다. 복구 기록은 telemetry export가 아니라 재시도 허용을 결정하는 내구 상태다.

## 검증과 한계

기존 코드에서 재시작·모델 변경 후 추가 재시도가 발생하는 실패를 확인한 뒤 수정했다. snapshot 복원, malformed 상태, checkpoint/tail 복원, 모델 상향 한도, 원본 오류 제외, 기록 실패 시 중단을 검증한다.

16번의 실제 TaskStore 저장·재로드 시나리오: 같은 목표를 유지했고 총 46번의 통제된 실패 호출 중 자동 복구는 누적 30회까지만 허용됐다. 16번째 실행에서는 추가 복구 없이 중단됐다. 이 시나리오는 약 0.59초의 가속된 로컬 테스트이며, 16시간 soak나 실제 모델 테스트가 아니다.

외부 모델·사이트 없이 fake planner/browser 경계와 실제 내구 저장소를 사용했다. 피드백 전달은 검증했지만 실제 모델 성공률·속도 향상은 아직 비교 평가하지 않았다.

최종 검증: 관련 테스트 **114 통과 / 0 실패**, 신규 테스트 별도 재실행 **9 통과 / 0 실패**. 마지막 수정 후 TypeScript 및 생성 코드 일치 검사 통과. `npm test -- --test-concurrency=1` 전체 검증 **1974 통과 / 0 실패 / 0 skipped**, 약 548.4초. 실제 Chromium 테스트도 포함됐다. 전체 테스트 실행은 장시간 실제 모델 평가 또는 타 제품과의 비교가 아니다.

독립 리뷰어 실행은 상속된 모델의 라우팅 오류로 불가능했다. 자체 소스 검토와 직접 회귀 검증만 수행했으며 독립 리뷰를 받았다고 주장하지 않는다. 다른 작업자의 변경을 보존했다. 커밋·푸시 없음.
