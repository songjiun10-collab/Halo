# 연구 모드: 호스트가 강제하는 출처 검증 (2026-10-13)

## 문제
`research` 능력은 "출처와 증거 검증이 구현되지 않음"이라며 막혀 있다가 이전 커밋(`d9dd8ce`)에서 열렸다. 그런데 실행 경로는 일반 브라우저와 같아서, 모델이 쓴 URL과 주장이 그대로 사용자에게 전달됐다(Codex 리뷰 P1). 이 설계는 그 빈자리를 호스트 코드로 메운다.

## 원칙
모델이 답을 쓰고, **어떤 출처를 인용할 수 있는지는 호스트가 정한다.** 인용할 수 있는 건 이 작업에서 호스트가 직접 열어 관측한 페이지뿐이다.

## 동작 (`main/harness/research-sources.js`, `task-controller.js`)
1. **출처 기록**: 연구 작업(`capability.id === "research"`)에서 호스트가 관측한 http(s) 페이지(오류 페이지 제외)를 `research_source` 노트로 저널에 남긴다(주소, 제목, 시각). 메모리의 기록은 저널에서 다시 만들 수 있어서 앱이 재시작돼도 보존된다.
2. **답변 검사**: 이 앱에서 답은 `need_user`의 `reason`으로 사용자에게 전달된다. 연구 작업의 그 텍스트에서 URL을 뽑아 기록과 대조한다. 같은 페이지 판정은 스킴, `www.`, 조각(`#`), 끝 슬래시, 추적 파라미터, 쿼리 순서를 무시한다.
   - 통과 조건: 인용한 URL이 모두 열어 본 페이지이고, **서로 다른 사이트(등록 도메인) 2곳 이상**.
   - 실패 사유: `no_sources`(인용 없음), `unverified_source`(열지 않은 페이지 인용), `too_few_sources`(독립 사이트 부족).
3. **통과하면** 모델의 답 뒤에 호스트가 만든 목록("Sources Halo opened (host-verified)": 제목, 주소, 연 시각)을 붙여 전달한다. 출처의 근거가 모델의 말에 있지 않다.
4. **실패하면** 답을 사용자에게 보내지 않고 플래너에게 돌려보낸다. 플래너는 `context.progress.research`로 인용 가능한 페이지 목록, 반려 횟수, 반려 사유, 열지 않은 URL을 받는다.
5. **반려는 최대 2번.** 그다음에는 답을 그대로 전달하되 `[Not verified by Halo: ...]` 표시를 붙인다. 사용자와의 소통을 막지 않고, 대신 검증 안 됐다는 사실을 숨기지 않는다. 반려 횟수는 저널에서 복원해서 재시작으로 초기화할 수 없다.
6. 저널에는 건수와 사유만 남고 반려된 답의 본문은 남지 않는다.

## 일부러 건드리지 않는 것
- 출처 없이 끝나는 질문(예: "어떤 주제를 조사할까요?")은 그대로 통과한다. 열어 본 페이지가 없고 URL도 없으면 사용자에게 묻는 말로 본다.
- `finish` 제안에는 본문이 없어서(증거 ID만 가짐) 이 검사의 대상이 아니다.

## 한계 (알고 쓸 것)
- **열어 봤다는 것과 그 페이지가 주장을 뒷받침한다는 것은 다르다.** 호스트는 "이 주소를 실제로 열었다"와 "서로 다른 사이트 2곳"만 확인한다. 본문과 주장의 일치, 출처의 신뢰도, 날짜의 최신성은 확인하지 않는다.
- 모델이 기억에서 답하고 URL을 하나도 쓰지 않으며 열어 본 페이지도 없으면(연구 작업인데 브라우징 없이 답하는 경우) 질문과 구별할 수 없어 검사하지 않는다.
- 같은 사이트의 여러 페이지는 출처 1개로 센다. 서로 다른 사이트가 서로를 베낀 경우는 구별하지 못한다.
- 검사는 영어/한국어 구분 없이 URL 형태만 본다. URL 없이 매체 이름만 쓴 인용은 "인용 없음"으로 취급한다.
- 검증은 단위 테스트(순수 로직 6개, 컨트롤러 흐름 6개)로만 확인했고 실제 모델과 실제 사이트로는 아직 돌려 보지 않았다.
