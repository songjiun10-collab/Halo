# 보호막과 객체 접근 검증 연결

> 이 문서는 애플리케이션 소유 메모리 객체의 참조 구현 범위를 설명한다. 현재 전체 실행·샌드박스 게이트 수치는 [REPORT_INDEX.ko.md](../REPORT_INDEX.ko.md)를 우선하며, 이 구현은 OS 격리 경계를 제공하지 않는다.

`protected_store::ProtectedStore`는 애플리케이션 소유 메모리 객체에 대한 실제 읽기를 수행하는 참조 구현이다. 매 읽기마다 검증기 가용성, 객체별 ACL, 보호막 판정을 확인하고 세 조건이 모두 통과한 경우에만 데이터 복사본을 반환한다. monitor의 Allow는 권한 검사를 대체하지 않는다.

- 정상 권한이 있어도 Block은 MonitorBlocked, 센서 누락·비유한 값에 따른 Revalidate는 EvidenceRequiresRevalidation 오류로 차단한다. 재검증이 완료되지 않은 요청에 데이터를 반환하는 우회 경로는 없다.
- 권한이 없으면 monitor가 Allow여도 읽지 못한다.
- 검증기 비가용은 VerificationUnavailable 오류이며 데이터가 반환되지 않는다.
- ACL 교체 후 이전 결과를 재사용하지 않는다. 권한 확인과 실제 읽기가 같은 불변 borrow 안에서 수행되어 이 메모리 모델에서는 중간 객체 교체가 불가능하다.

신뢰 경계: principal은 호스트가 인증한 신원이어야 한다. put과 set_verifier_available은 신뢰된 관리자 API다. 요청 본문이 신원이나 ACL을 선택하게 노출하면 안전하지 않다. 이 구현은 인증 시스템, 외부 파일 경로, 임의 코드 실행, 네트워크 또는 OS 샌드박스의 보호를 제공하지 않는다.

회귀 실험은 1,000단계 × 5조건(전손·정상·공통 오프셋·단일 센서 급증·NaN)에서 권한이 있는 요청과 금지 요청을 각각 실행하여 총 10,000건의 실제 메모리 읽기 시도를 검증한다. 권한과 보호막을 모두 통과한 경우의 데이터 반환 및 나머지 경우의 오류 반환을 직접 검사한다. 각 채널의 누락·NaN·양/음의 무한대, 권한이 있는 요청의 Block, 검증 실패와 ACL 회수도 별도 테스트한다. 이 결과는 모델의 탐지율 개선을 입증하지 않는다.

남은 한계: Shift의 극단 잡음 FPR 및 센서 전손 가용성 문제를 해결하지 않았다. 차단 우선 정책이므로 오탐과 증거 누락은 정상 사용자의 접근도 거부한다. 신뢰된 호스트가 제공하는 신원·ACL·증거·Shield 설정이 변조되면 이 구현만으로 막을 수 없다. 실제 배포에는 해당 제품의 인증·권한 저장소 및 사용 시점의 실행 경로와 연결해야 한다. 외부 검증기 장애 중 정상 가용성은 보장하지 않는다. 이 참조 구현은 절대적인 침해 불가능성을 보장하지 않는다.

```sh
cargo test --release --locked --manifest-path rust/Cargo.toml protected_store
```
