# HALO Shift Benchmark v2

> 2026-09-21 후속 상태: **연구 한계**. [보고서별 조치 원장](../docs/reviews/REPORT_REMEDIATION.ko.md)에서 수정·재현과 잔여 범위를 구분한다. 아래 과거 수치는 현재의 전체 해결 판정이 아니다.

## v2 버그 수정과 재검증

v1은 센서 손실·꼬리 잡음의 난수 소비가 기본 표본을 바꾸고, 상관 교란 강도 0에서도 기본 공통 잡음이 사라지는 결함이 있었다. v2는 기본 난수와 교란 난수를 분리하고 교란 난수를 조건과 무관하게 일정하게 소비한다. 상관 교란은 기본 공통 잡음 0.2에서 시작한다. 따라서 같은 seed에서 센서 손실은 대상 센서만 바꾸고, 강도 0은 모든 도메인에서 clean과 동일하다.

E002 평균은 최댓값으로 정규화한 뒤 계산하여 큰 유한 점수의 합산 오버플로를 방지한다. 기존 Python 기준값 비교도 통과했다. 세 결함의 재현 테스트와 강도 간 교란 대응·극단값 부호/상쇄 테스트를 포함한 Rust 실험 테스트 47개, 샌드박스 테스트 12개가 통과했다.

v2 실행 결과는 `rust/results/shift-bench-v2.json`에 1,920행으로 저장한다. 아래 v1 결과 표는 과거 기록이며 v2 결과로 해석하지 않는다. 난수 생성과 분포 정의가 바뀌었으므로 v1/v2 차이를 방어 알고리즘 개선량으로 해석할 수 없다.

공개 벤치마크의 평가 방법을 참고해 HALO E002의 실제 점수 통합 함수를 검사하는 Rust 실행기다. 공식 WILDS·RobustBench 데이터셋이나 모델은 사용하지 않으며, 공식 점수와 비교할 수 없는 합성 파생 벤치다.

## 참고한 공개 평가 방법

- [WILDS 데이터셋 설명](https://wilds.stanford.edu/datasets/): 도메인 일반화, 하위 집단 비율 변화, 최악 집단 평가. HALO에서는 보정용 정상 데이터와 평가용 정상·공격 데이터의 seed를 분리하고, 도메인별 최악 공격군 탐지율과 공격군 비율 변화에 따른 가중 탐지율을 기록한다.
- [RobustBench](https://robustbench.github.io/): 명시된 위협 조건에서 표준화된 여러 평가를 통한 강건성 측정. HALO에서는 고정된 교란 종류·강도·오탐 예산으로 모든 점수 통합 방식을 평가한다. AutoAttack이나 이미지 교란 알고리즘 자체를 구현한 것은 아니다.

## 기존 hard_bench와 달라진 점

1. 임계값은 별도의 깨끗한 정상 데이터에서 한 번 고정한다. 평가 도메인이 바뀌어도 다시 보정하지 않는다.
2. clean 1개 + 교란 5종 × 강도 3개 = 16개 도메인 조건을 평가한다. 교란은 상관 잡음, 꼬리가 긴 잡음, 4번째 센서 손실, 점수 오프셋, 복합 교란이다. 정상·공격 모두 동일한 도메인 변환을 받는다.
3. 공격군 4개를 별도 집계한다. 각 공격군은 해당 센서 하나에만 평균 +3.4 신호가 있고 나머지 평균은 0이다. 기존 E002의 알려진 공격 생성 분포와도 다르므로 과거 E002 점수를 직접 비교하지 않는다.
4. 평균 TPR, 최악 공격군 TPR, held-out FPR, 원시 분자·분모, Wilson 95% 구간을 기록한다. 마지막 집단의 비중을 0.1%와 90%로 바꾼 재가중 점수도 제공한다.
5. 전체 공격 발생 비율을 0.1%/1%로 가정한 정밀도를 기록한다. 이는 균등 공격군 혼합의 TPR로 계산한 가정값이다.

보정·정상 평가·공격 4군의 seed는 각 반복에서 `seed*10000 + 0..5`로 분리한다. 환경 강도 간에는 같은 seed를 재사용하여 비교를 대응시킨다. 같은 표본으로 여러 방식을 평가하므로 결과 행을 독립 관측 수로 세면 안 된다.

판정은 `score >= threshold`다. 보정 데이터에서 `floor(n*target_fpr)`건 이하만 오탐하도록 경계 점수 바로 위의 부동소수점을 사용한다. 동점은 보수적으로 제외한다. n=1만·목표 FPR 0.01%는 보정 허용 1건뿐이므로 정밀한 극저오탐률 인증에 충분하지 않다. Wilson 구간은 조건별 구간이며 전체 1,920행에 대한 동시 보장이 아니다.

## v1 과거 실행 결과 — 2026-09-13

표본 1만/집단, seed 5개, HALO 8개 방식, 오탐 예산 0.01%·1%·10%로 총 **1,920행**을 생성했다. 검증한 보정 오탐 예산 위반은 없었다. 종료 코드 0은 실행·보정 검증 완료이며 방어 성능 합격을 뜻하지 않는다. 평가 데이터의 예산 초과는 `empirical_fpr_exceeds_budget`에 남긴다. 운영 게이트가 필요하면 `--fail-on-fpr`를 추가하며, 이 경우 평가 데이터에서 목표 FPR을 한 행이라도 넘으면 JSON 저장 후 종료 코드 1로 실패한다.

evidence_diverse, 보정 목표 FPR 1%, seed 5개 평균:

| 환경 | 평가 FPR | 최악 공격군 TPR | 공격군 평균 TPR |
|---|---:|---:|---:|
| 깨끗한 평가 | 1.088% | 3.004% | 23.501% |
| 센서 손실 100% | 0.002% | 0.002% | 1.639% |
| 복합 교란 최대 강도 | 25.944% | 25.704% | 40.400% |

복합 교란에서 TPR 상승은 FPR 폭증을 동반한다. 센서 손실에서는 독립 증거에 기대던 탐지력이 사라진다. 이 결과는 생성한 점수 환경에 한정되며 실제 LLM 탈옥·OS 탈출 결과가 아니다.

## 재현

```sh
cargo build --release --locked --manifest-path rust/Cargo.toml --bin shift_bench
rust/target/release/shift_bench --n 10000 --seeds 5 --output rust/results/shift-bench-v2.json
cargo run --release --locked --manifest-path rust/Cargo.toml --bin shift_bench -- --n 10000 --seeds 5 --fail-on-fpr --output rust/results/shift-bench-gated.json
cargo test --release --locked --manifest-path rust/Cargo.toml
```

프로젝트 로컬 툴체인은 README의 `RUSTUP_HOME`/`CARGO_HOME` 접두사를 사용한다. n 범위는 100–100만, seed 수는 1–100이며 큰 설정은 메모리와 시간이 많이 필요하다. 원시 결과는 Git에서 제외되는 `rust/results/shift-bench-v1.json`에 저장한다.

새 회귀 테스트는 보정 동점·0 예산, 실패 0건의 불확실성, 도메인 간 임계값 고정과 공격군 누락을 검사한다.
