# 실제 임시 샌드박스 벤치마크

> 아래는 과거 실험 기록이다. 현재 결과 파일은 다시 생성되었으며, 최신 수정과 남은 정보 노출은 [2026-09-12 재검증](RECHECK.ko.md)에 기록한다.

2026-09-11, macOS 27.0 / Apple Silicon, 로컬 Python 3.12에서 실행했다.
이 디렉터리는 조사용 프로토타입과 실행 증거다. 운영용 실행기나 공개 표준 벤치마크가 아니다.

## 결과

9개 공격과 3개 정상 작업을 조건별 5회 반복했다. 전체 180개 프로세스 실행에서 실행 오류·타임아웃·판정 불명은 0개였다.

| 실행 조건 | 공격 성공 | 공격 차단 | 정상 작업 성공 | 프로세스 실행 시간 중앙값 |
| --- | ---: | ---: | ---: | ---: |
| 격리 없는 양성 대조군 | 45/45 | 0/45 | 15/15 | 47.161 ms |
| OS 샌드박스 + 미끼 환경변수·FD 전달 | 10/45 | 35/45 | 15/15 | 56.898 ms |
| 같은 OS 샌드박스 + 환경 초기화·미끼 FD 미전달 | 0/45 | 45/45 | 15/15 | 56.661 ms |

9개 공격은 절대경로 읽기, `../` 우회 읽기, 심볼릭 링크 읽기, 절대경로 쓰기, 심볼릭 링크 쓰기, 자식 `/bin/cat`을 통한 읽기, loopback TCP 연결, 환경변수 읽기, 상속받은 파일 디스크립터 읽기다.

추가 탐색에서 작업 디렉터리 안에 외부 미끼 파일의 하드링크를 미리 심은 경우를 별도로 실행했다. `sandbox-exec`는 경로가 허용된 작업 디렉터리의 파일로 판단해 하드링크를 통한 외부 파일 읽기와 쓰기를 모두 허용했다. 따라서 OS 프로파일만으로는 이 alias를 제거할 수 없다. 실행 전 작업 디렉터리의 일반 파일을 순회해 `st_nlink != 1`인 파일을 거부하는 사전 검증을 추가했고, 이 검증을 회귀 테스트로 고정했다. 심볼릭 링크는 기존 공격 목록처럼 프로파일에서 차단됐다.

외부 사례도 capability 관점으로 반영했다. Microsoft가 분석한 CVE-2022-26706은 샌드박스 프로세스가 `/usr/bin/open`과 Launch Services를 이용해 샌드박스 밖 앱을 시작하는 체인을 설명한다. [Microsoft의 분석](https://www.microsoft.com/en-us/security/blog/2022/07/13/uncovering-a-macos-app-sandbox-escape-vulnerability-a-deep-dive-into-cve-2022-26706/)에 따라 프로파일에서 진입점 Python 프레임워크 경로만 `process-exec`를 허용하고 `open`, 셸, 기타 자식 실행은 차단했다. Chromium의 Seatbelt 문서가 지적하는 사전 열린 FD 예외도 확인해 clean launch에서는 `pass_fds`를 비우고 환경을 새로 만들도록 유지했다. [Chromium sandbox 문서](https://chromium.googlesource.com/chromium/src/+/master/sandbox/mac/)는 이 FD 동작을 명시한다.
정상 작업은 계산, 작업 디렉터리 파일 읽기, 파일 쓰기 후 읽기다.

환경변수·FD를 전달한 조건에서는 두 유출 경로가 각각 **5/5회 성공**했다. 파일 경로 접근이 `EPERM`으로 막혀도 `os.pread()`로 상속된 FD에서 미끼 비밀값을 읽을 수 있었다. 이는 이번에 만든 실행 조건의 capability 전달 누수이며, macOS 커널 취약점 발견을 의미하지 않는다.

보완 조건에서는 허용 목록으로 환경을 새로 만들고 `close_fds=True, pass_fds=()`로 실행했다. 환경변수는 존재하지 않았고 해당 FD 읽기는 `EBADF`로 실패했다. 자식 프로세스의 파일 접근도 거부되어, 조사한 경로에서는 격리 정책이 자식에게 유지됨을 확인했다.

## 실험 방법과 판정

- 매 실행마다 새 임시 디렉터리에 작업 영역과 외부 미끼 영역을 만들었다. 실제 사용자 비밀정보는 읽지 않았다.
- 외부 미끼 파일의 무작위 문자열과 같은 값을 읽었을 때만 읽기 공격 성공으로 판정했다. 쓰기 공격은 부모가 실제 변경까지 확인했다.
- TCP 공격은 이 실험이 연 `127.0.0.1` 리스너에만 연결했다. 격리 없는 대조군에서 동일 코드가 성공하는지 확인했다.
- 시작 실패, 잘못된 출력, 예상하지 못한 OS 오류, 타임아웃은 차단 성공으로 세지 않고 오류로 분리했다.
- 프로파일은 `deny default`로 시작한다. 작업 디렉터리에 읽기·쓰기를 허용하고 시스템/Python 런타임 경로에는 읽기를 허용한다. 파일 메타데이터 조회와 프로세스 실행·생성은 허용한다. 네트워크는 허용하지 않는다.
- 초기 최소 프로파일에서는 `/bin/echo`와 Python이 시작 중 종료됐다. 진단 결과 루트 디렉터리 **자체**의 읽기 허용 `(literal "/")`가 필요했다. 루트 아래 전체를 허용하는 `(subpath "/")`는 사용하지 않았다. 최종 정상 대조군은 모두 실행됐다.
- 실행 시간은 프로세스 시작·sandbox-exec·Python 초기화·작업·출력 회수까지 포함한다. 조건은 순서대로 실행했으며 5회 반복은 성능 비교의 통계적 신뢰구간을 제공하지 않는다.
- 임시 파일과 리스너는 실행 후 정리됐다. 결과의 `temporary_fixtures_removed`는 `true`다.

## 재실행

저장소 루트에서 macOS Python으로 실행한다. 별도 패키지는 필요하지 않다.

```bash
.venv/bin/python artifacts/sandbox_benchmark/run_benchmark.py --repeats 5
```

`results.json`에 실행별 결과, errno, 종료 코드, 소요 시간, 프로파일을 기록한다. 미끼 비밀값은 마스킹한다. 대조군 공격의 실제 성공, 모든 조건의 정상 작업 성공, 보완 조건의 모든 공격 차단이 확인되고 오류가 없어야 종료 코드 0을 반환한다.

## 검증 범위

이 결과는 macOS에서 실행한 **고정된 9개 공격**에 대한 것이다. 실제 LLM이나 적응형 공격 에이전트, Linux/Docker/VM, 커널 취약점, Mach IPC, 상속된 소켓, 하드 링크·경로 경합, CPU·메모리 고갈, 프로세스 수 제한, 장기 실행 및 자식 프로세스 트리 정리는 검증하지 않았다. 파일 메타데이터와 런타임 읽기 예외가 있으므로 전체 호스트 파일의 비밀성도 주장하지 않는다. 표준 입출력은 결과 회수를 위해 열려 있다.

보완 조건의 0/45는 독립적인 공격 45종이 아니라 9종을 5회 반복한 결과다. 이 수치로 임의 코드의 완전한 격리나 AI containment 보장을 주장할 수 없다.

## 함께 수정한 실험 코드 버그

1. E001·E001-B·E003: 작은 표본에서 안전/위험 클래스가 비어 있으면 발생하던 `ZeroDivisionError`를 수정했다. 관측이 없는 클래스의 조건부 비율은 `NaN`으로 반환한다. 분모가 없는 결과를 0% 실패 또는 100% 성공으로 해석하면 안 된다.
2. E004: 점수 또는 가중치의 `NaN`·무한대를 `ValueError`로 거부한다. 이전에는 NaN 점수가 비교에서 조용히 미탐/비차단으로 처리됐다.
3. E004: 유한한 큰 가중치의 합이 무한대로 넘쳐 50% TPR이 0%로 계산되던 문제를 수정했다. 최대 가중치로 스케일링한 뒤 가중 평균을 계산한다.
4. 전체 실험 입력 경계: 확률·비율은 유한한 `[0, 1]`, 표본 수와 지연·윈도우는 양의 정수(지연·윈도우는 0 허용)인지 먼저 검사한다. 잘못된 입력이 NumPy의 모호한 오류나 조용한 확률 왜곡으로 이어지지 않게 했다.
5. 샌드박스 작업 영역: 외부 inode를 가리키는 사전 존재 하드링크를 실행 전에 거부한다. 경로 기반 macOS sandbox만으로는 하드링크 alias를 구분할 수 없다는 한계를 실행 결과에 반영했다.

추가한 회귀 테스트 56개가 해당 오류와 입력 경계를 고정한다. 수정 후 기존 21개를 포함한 77개 테스트가 통과했고, Python 컴파일 및 `git diff --check`도 통과했다.
